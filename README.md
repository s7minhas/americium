# The American Break: International Cooperation in 2025

The paper has two manuscript files: [main.tex](paper/main.tex) and [si.tex](paper/si.tex). They share [references.bib](paper/references.bib). Prose paragraphs occupy one source line. The compiled versions are [main.pdf](paper/main.pdf) and [si.pdf](paper/si.pdf).

For replication, distribute `data/` and `results/` together with the code and paper. These directories and PDFs are covered by `.gitignore`; a source-only checkout is insufficient. The retained input snapshots, starting states, posterior draws, source archive and audit receipts are part of the replication materials. Local installed libraries and compiler caches are rebuilt and need not be distributed.

This README is the replication guide. It lists the commands that regenerate the paper's numbers, figures and tables, identifies the outputs used in each display, and records requirements and runtimes.

Run commands from the project directory. The R files produce the observed comparisons, adoption history, publication figures, economic checks, model inputs and estimates, or implementation checks. `sampler.cpp` contains the compiled model updates. The archives in `code/vendor/` pin the model package and its required `netify` version.

Requirements: R with `data.table`, `digest`, `ggplot2`, `ggrepel`, `RColorBrewer`, `jsonlite`, `posterior`, `Rcpp`, `RcppArmadillo`, `readxl`, `rvest`, and `xml2`; a C++ compiler and the dependencies declared by the archived R package; Python with `numpy` and `pandas`; and LaTeX with `latexmk`, `pdfinfo`, `pdftoppm`, `pdftotext`, and `pdfcrop`. Optional source refreshes also use Python `requests`. The model package also requires `netify` 1.5.3 or later, `ggforce`, `gridExtra`, `coda`, `patchwork`, `cli`, `MASS`, `Matrix`, and `abind`. The bundled `netify` source requires `RcppEigen`, `rlang`, `checkmate`, `igraph`, `ggnewscale`, and `withr`, in addition to packages already listed. Install these prerequisites into a library visible in `.libPaths()`; set `R_LIBS_USER` to that library when needed. Do not rely on a personal `.Rprofile` to make dependencies visible. The tested versions and environment are retained with the replication receipts in `results/checks/io_review.zip`.

Install the bundled dependency after its prerequisites are available:

```bash
Rscript -e 'install.packages("code/vendor/netify_1.5.3.tar.gz", repos = NULL, type = "source")'
```

The model commands install the pinned `lame` source automatically into `code/.library` and compile the project backend. A failed source installation stops execution rather than falling back to another installed version. Reconstructing observations and model inputs does not require downloading new data.

Rebuild the observed results, trade checks, and model inputs:

```bash
export OPENBLAS_NUM_THREADS=1
export OMP_NUM_THREADS=1
export MKL_NUM_THREADS=1
Rscript code/01_observed_votes.R data results
Rscript code/02_adoptions.R data results
Rscript code/03_economic.R trade
Rscript code/03_economic.R detail
Rscript code/02_adoptions.R events
Rscript code/02_adoptions.R proposals
Rscript code/07_proposal_comparison.R
python code/09_measure_text_reuse.py measure data/resolution_texts.zip results/text_reuse
Rscript code/09_text_reuse.R
Rscript code/10_models.R prepare
```

`code/09_text_reuse.R` reads `results/adoptions/history/all_adoption_units.csv`, so run it after `code/02_adoptions.R data results`. The text measure needs only Python's standard library; `requests` and `pdftotext` are needed only by the `fetch` and `letters` modes that document how the texts were obtained.

If the supplied model draws and summaries remain in `results/`, regenerate the four voting and text figures with `Rscript code/19_figures.R data results` and `Rscript code/09_text_reuse.R`. The first command includes the supplement's trade shares and flows figure. `Rscript code/12_reset_probabilities.R` computes country-year reset probabilities and participation and reset-rate checks from retained draws; it does not refit models. Figures require these model outputs and come after fitting in a reconstruction from an empty results directory. To redraw only the voting-position maps, use `Rscript code/19_figures.R data results space-layout`; this reads retained display summaries. Check the implementation with `Rscript code/21_validate.R`.

To replay a reported voting-model run, use `Rscript code/10_models.R fit un 8`; `controls` replays the simulated controls. The retained `trade` mode belongs to an earlier exploratory analysis and is not used for claims in the current manuscripts. The last argument sets the number of processes. The inputs are rebuilt from the retained observations. The reported runs start from the archived model and random-number states in `data/model_initial_states.rds`; `data/model_chains.csv` records their settings and completed budgets. Earlier diagnostic runs used to develop the sampler are excluded in full. Each reported run discards its specified additional warmup, then retains every sampling draw from that run and its checkpoint extensions. The chain plan records the additional UN update for latent geometry and the trade update for reset indicators. Completed segments and interrupted runs preserve their full model and random-number states. `Rscript code/10_models.R summarize un 8` regenerates posterior summaries from these fits. Replays write to `results/models/un_replay/` (or the corresponding domain), preserving the archived results. The `cold` mode instead starts new chains from random positions and writes to a separate directory. The release retains the initial states and per-draw quantities used in the paper. The restored spatial figures also retain their original coordinate draws and pairwise-distance draws in `results/models/un/space/draws.rds`; these figures can be reconstructed without replaying the models. Full fit objects and checkpoints are generated when a model is replayed.

For a reconstruction starting with an empty results directory, run the observation and input commands above, then replay and summarize the voting model and its simulated controls. The replay was tested with R 4.3.3 on 64-bit Ubuntu 24.04.3. The worker count below is eight for fitting and four for summarizing; lower it if memory or CPU availability requires it. These commands use process forking on Linux or macOS. On native Windows, use one worker, or run the Linux workflow through WSL.

```bash
Rscript code/10_models.R fit un 8
Rscript code/10_models.R summarize un 4
Rscript code/10_models.R fit controls 8
Rscript code/10_models.R summarize controls 4
Rscript code/19_figures.R data results space-extract results/models/un_replay/fit_manifest.csv
Rscript code/19_figures.R data results
python code/23_build_manuscripts.py
```

The spatial extraction command selects the four full-UN chains from the replay manifest automatically. The other replay summaries remain in the domain directories ending in `_replay` for comparison with the supplied release. Keep a separate reference copy when testing a reconstruction; replay files and release audit receipts serve different purposes. The archived release receipts record the earlier reviewed sources; new revision checks are stored separately and do not replace those receipts. PDF creation dates and runtime paths can differ without changing figures or numerical results.

`code/17_trade_replay.R` retains historical exploratory trade fits and verification steps. The current paper and supplement report only observed trade; neither the fits nor the planted reallocation comparison supports their claims. For historical inspection, `current_baseline` and `partner_reallocation_terminal` remain available. The fit command replays the two relevant chains into `results/models/trade_space_replay/SPECIFICATION/` from retained observations, priors, starting states, random-number states and run budgets:

```bash
Rscript code/17_trade_replay.R fit current_baseline 2
Rscript code/17_trade_replay.R verify current_baseline
Rscript code/17_trade_replay.R fit partner_reallocation_terminal 2
Rscript code/17_trade_replay.R verify partner_reallocation_terminal
Rscript code/18_trade_relations.R
```

Verification compares retained features with the released trade results and checks the source fingerprints recorded when each fit was created. Historical fit fingerprints refer to the historical script names and contents; they cannot certify reformatted or renamed source files. Fresh fits record the current source names and fingerprints. Numerical summaries and historical receipts remain separate records. Use the prerequisite R library from the replication environment, setting `R_LIBS` explicitly when it is outside the default search path.

For the supplied release, build both documents:

```bash
python code/23_build_manuscripts.py
```

Source and retrieval dates are preserved with the voting archive, official UN adoption pages, IMF responses, and the US Census country workbook. The IMF comparison revises 2024–2025 while retaining the earlier source vintage. The Census comparison uses complete annual observations from one workbook vintage for 1992–2025; a new download requires a new source audit and a fresh claim review.

The substantive resolution review is in `data/resolution_review.csv`, with its sources in one archive, `data/resolution_sources.zip`, and retrieval records in `data/resolution_sources.json`. It covers all 29 American vote-switch comparisons and all 33 newly recorded comparisons discussed in the supplement. `02_adoptions.R` reproduces the counts and vote contributions in `results/adoptions/content/`. The classifications record both continuity and changed provisions. Automatic meeting transcripts are identified separately from official records; missing requester evidence remains missing.

The targeted `detail` command reproduces the Census product accounting, monthly and quarterly comparisons, and price-data coverage from retained sources in `data/census/detail/` and `data/census/prices/`. It preserves the existing country-series vintage and writes to `results/trade/census/detail/`; missing price months are not imputed. The `events` command checks the documentary panel in `data/resolution_events.csv` and reproduces its inventory. The existing resolution archive also retains the fixed selection design, source passages, initial independent coding and adjudications. These cases document choices over texts, not institutional implementation or a newly coordinated response to the United States.

The proposal study starts with all 128 formally considered substantive Second Committee proposals in 2023–2025. The four linked inputs are `data/resolution_proposals.csv`, `data/resolution_proposal_links.csv`, `data/resolution_commitments.csv`, and `data/resolution_demands.csv`. `Rscript code/02_adoptions.R proposals` reproduces cohort dispositions, content categories, equal-proposal retention bounds, both baseline comparisons, earlier-draft and matched-family sensitivities, and recorded American votes in `results/adoptions/proposals/`. It also reproduces distinct amendment, demand, position-coverage and conditional-expectation summaries in `results/adoptions/process/`. It reads retained inputs without downloading sources or fitting models. `Rscript code/19_figures.R data results trade` rebuilds only the supplement’s two-panel trade shares and flows figure.

The source archive preserves the earlier resolution review and documentary panel. Its `proposal_study/` members add the full considered-proposal inventory, initial agent readings, reconciliations, exact source passages and corrections. The authoritative content coding is the four project CSVs with `proposal_study/adjudication/acceptance.json`; archived earlier coding files remain historical records. `packet_archive_member` in the commitment data and `authoritative_source_archive_member` in the demand data identify retained evidence. `proposal_study/path_map.json` resolves original acquisition paths; older proposed archive names inside acquisition logs are superseded by these locators and the member manifest in `data/resolution_sources.json`. No analysis command requires the original scratch directory.

The text-reuse study is a third, separate content analysis and involves no model judgment. `data/resolution_texts.zip` holds the extracted text of 10,880 adopted General Assembly resolutions (sessions 44 to 80), `manifest.csv` with every request, address and PDF SHA-256, and `manifest_all_attempts.csv` including failed lettered-symbol attempts; `data/resolution_texts.sha256` lists file checksums. The PDFs are not retained; the manifest records the address each was served from and its SHA-256. `python code/09_measure_text_reuse.py measure data/resolution_texts.zip results/text_reuse` recomputes every pair score and series from the archive without downloading anything. `Rscript code/09_text_reuse.R` then joins American votes, the hand review and the request coding, and writes the tables in `results/text_reuse/` and the figure `results/figures/text_carried_forward.pdf`. The `fetch` and `letters` modes document how the texts were obtained and need Python `requests` and `pdftotext`; do not rerun them to reproduce results. Sessions 44 to 47 are mostly scans and are unused.

The comparison of successive adopted decisions is a separate study from the within-year proposal study and uses different stages and denominators. Its complete record (sources, failed-access receipts, first and second readings, reconciliations, the 18 accepted batches and 72 accepted input tables, code, tables and review files) is preserved in `data/proposal_comparison_sandbox.zip`, with file-level checksums in `data/proposal_comparison_sandbox.sha256`. Both are covered by `.gitignore` and must be distributed with `data/`. `Rscript code/07_proposal_comparison.R` verifies the archived files against the preservation checksums, rebuilds all request-level and initiative-level tables from the 72 accepted input tables, and reproduces the equal-initiative shares, feature subsets and leave-one-out ranges into `results/proposal_comparison/`. It stops if an integrity check fails or any reconstructed table differs from the archived accepted result. The production command does not depend on the original temporary directory: it extracts the archive into a fresh temporary directory and writes only its chosen output directory. Original acquisition paths remain in provenance records; for paths beginning `/tmp/americium_proposal_sandbox/`, the remainder identifies the member of `data/proposal_comparison_sandbox.zip`. The original archived script retains its historical production-protection check. The archive preserves the original production-protection receipt as historical evidence, rather than comparing the revised paper to that old snapshot. The older process tables retain their original family identifiers, which are not the same namespace as the cross-year text inventory. Link those studies through `root_id`, not through `family_id`; the existing selected process-to-request links additionally identify exact request IDs. The authors manually recoded and checked the final request comparisons against the source texts and confirmed that the final classifications are unchanged. Earlier readings and reconciliations retain their original provenance in the archive. Their inter-reading agreement and reading-based continuity bounds are no longer reported as validation of the final manual coding. For independent validation, `work/human_review/` in the archive holds a fixed packet of 217 whole-text pairs; the sample size must be chosen before outcomes are viewed.

Content changes are not all bargaining concessions: a completed activity may be replaced by an acknowledgment. Added requests have a separate denominator and do not offset lost initial requests. Unknown correspondence and ambiguous material classification remain bounded; missing national votes and missing statements are not imputed. Two unnumbered internal decisions have no separate issued draft, so both source-stage comparisons use their recorded decision passages. The new population study is distinct from the earlier illustrative panel of thirteen families. The September 2026 newspaper article retained under `context/` is later contextual evidence, outside every empirical comparison.

The compact author-review packet is `results/checks/io_review.zip`. It retains the five fresh simulated referee reports, responses to their seventeen issues, focused rereviews, independent source/arithmetic audit receipts, reviewed claim-binding changes, and draft submission materials. These are AI-assisted checks and reviews, not journal decisions or completed human recoding. Historical claim receipts remain in `results/checks/claims.json` and `checks.csv`; `build.json` records the latest successful document build. An earlier sweep reproduced 190 derived tables in isolation and independently recalculated the headline voting, proposal-retention and Census results; its receipt is under `final_adversarial_sweep/` in the same archive.

The subsequent full computational replication is recorded under `top_to_bottom_replication/` in that archive. It reconstructed the observations and model inputs in a separate directory, reran all 214 reported chains, and regenerated the figures and both documents. This exposed an array-memory defect in three sampler routines: R could reclaim an array while C++ still used it. The corrected routines retain their own copies. Forced collection and memory reuse fail with the old code and pass with the repair; `21_validate.R` now checks this behavior. The corrected runs pass all convergence requirements and all 990 registered numerical claims at the paper's reported precision. An independent repeat of the affected UN chain matches every saved feature exactly. All eleven figure renders and all 61 document pages match the earlier version. The audit records the original discrepancy and the comparisons; it does not assert that every original posterior draw was unchanged. These checks reproduce computations from retained sources and starting states, rather than independently recoding every source document.

The country maps align each year to the same reference by rotation or reflection, preserving within-year distances and fitted relationships. Alignment leaves the saved coordinate draws unchanged. `Rscript code/19_figures.R data results space-summarize` reproduces their coordinate summaries, distance histories and diagnostics from the retained plotting draws; `Rscript code/19_figures.R data results space` redraws the two spatial figures used in the manuscript. `space-extract` takes a fourth argument naming the UN replay manifest, or a manifest already restricted to the four full-UN chains, when recovering those plotting draws. The accepted replay and independent numerical checks are recorded in the existing author-review archive.

The main paper uses `cooperation_space.pdf`, `historical_space_shifts.pdf`, `allied_history.pdf` and `text_carried_forward.pdf`. The supplement uses `trade_shares_flows.pdf`. Their generators retain only these publication plots. Group-distance summaries remain because they document the alignment and distance calculations. `Rscript code/19_figures.R data results agreement-history` redraws only the recurring-vote history from existing estimates and reweighting ranges. Earlier figure inventories and writing reviews remain historical audit records in `results/checks/io_review.zip`.

The R and Python scripts use two-digit prefixes for their workflow stages. `00_data_helpers.R` standardizes voting and Census column names at import, `00_plot_style.R` supplies the common publication theme, and `00_sampler.R` loads the pinned statistical backend. Scripts `01`–`09` construct observed comparisons and text summaries; `10`–`18` fit or summarize the statistical analyses; `19` prepares tables and figures; `20` checks numerical summaries; and `21` validates the sampler. The numbered model stages have separate preparation, fitting and summary modes; use the commands below rather than running every file without arguments. Related R and Python scripts share a stage number: `03_prepare_imf_trade.py` supplies the trade data, `09_measure_text_reuse.py` calculates wording reuse, and `19_assemble_tables.py` assembles the result tables. The optional source utility is `00_archive_document_sources.py`. Stages `22`–`24` check reported numbers, build the manuscripts and check the compiled files. All Python entry points live in `code/`; the pinned vendor archives retain their package filenames. The unused human-validation script and generators for plots absent from the current manuscripts have been removed.

## Reproducing the November revision

The revision analyses use retained sources. Run the ordinary commands from the repository root with the thread limits above. No command below refreshes external sources unless it explicitly says `fetch` or `download`.

1. `Rscript code/05_allied_agenda.R`: builds the recurring, newly recorded and unmatched agenda comparisons in `results/observed/allied_agenda/` from the retained votes and adoption inventory.
2. `Rscript code/13_model_threshold.R`: reads the released UN coordinate draws and chain features; writes the threshold, displacement, fitted-change decomposition and held-draw scale checks under `results/models/un_variants/threshold/`, `decomposition/` and `kappa_sensitivity/`.
3. `Rscript code/14_model_benchmarks.R`: reads the network arrays, participation probabilities and simulated controls; writes model-free ranks to `benchmarks/` and final-period artifact summaries to `signatures/`.
4. `Rscript code/15_ideal_points.R compare`: compares retained dynamic ideal points with the released coordinate draws in `results/models/un_variants/ideal_points/`. `download` is a separate source-refresh mode; the ordinary comparison is offline.
5. `Rscript code/16_followers.R`: reads votes, member-group metadata and released estimates; writes member responses, named votes, group comparisons, tax votes and individual ally tables to `results/observed/followers/`.
6. `Rscript code/04_ally_selection.R`: checks the fixed group against archived treaty, income and GDP sources, writing `results/observed/ally_selection/`. Its optional `merge` argument updates the added selection columns in `data/member_groups.csv`; it is not needed to reproduce tables.
7. `Rscript code/06_agenda_harmonization.R`: writes the expanded title and predecessor comparisons to `results/adoptions/harmonized/`, keeping the automatic and reviewed title-link rules separate.
8. `Rscript code/08_reading_agreement.R`: historical diagnostic checking the archived first and second request readings and their freeze records; writes agreement, confusion counts, reconciliation summaries and conservative continuity bounds to `results/proposal_comparison/reading_agreement/`. These earlier reading-based diagnostics are no longer reported in the manuscript. The script does not draw a human-validation sample.
9. `python code/09_measure_text_reuse.py terms data/resolution_texts.zip results/text_reuse`: writes term counts and header-stripped exact paragraph comparisons. Run after the retained `pairs.csv` exists. The released approximate-match series and the header-stripped checks retain separate outputs.
10. `Rscript code/18_trade_relations.R`: historical exploratory diagnostic, no longer reported in the manuscripts; reads the retained trade fits and reproduces model-versus-observed relationship contrasts in `results/models/trade/relations/`; its fit prerequisites are listed above.
11. `Rscript code/19_figures.R data results trade`: draws the supplement’s two-panel `trade_shares_flows.pdf` from the retained Census levels.
12. `python code/19_assemble_tables.py`: combines completed variant summaries and the observed analysis outputs into `results/revision/variant_comparison.csv`, `trade_checks.csv` and table fragments with source hashes. The full comparison retains exploratory runs; manuscript fragments select converged fits that address substantive questions.
13. `Rscript code/20_numerical_checks.R`: recomputes reported posterior means and terminal probabilities from retained features and vote totals from the underlying archive, and checks historical reading agreement from archived confusion counts; writes `results/revision/numerical_checks.csv`. Implementation validity and empirical convergence are assessed separately.
14. `python code/22_check_reported_numbers.py`: recalculates the historical numeric registry and checks the source-to-manuscript bindings. Outputs are `results/revision/retained_claim_checks.csv`, `claim_check_summary.json`, and `new_numbers.csv`. The archived historical text bindings are not treated as current manuscript bindings.
15. `python code/00_archive_document_sources.py verify`: verifies the new source archive's retrieval checksums. Its `fetch` mode downloads missing public sources and preserves completed retrievals; it is unnecessary for ordinary reproduction.
16. `python code/23_build_manuscripts.py`: builds both revised manuscripts and records page counts, source hashes and warning checks in `results/checks/build.json`.

The analysis scripts above generally take seconds to minutes when the retained draws are supplied; posterior-coordinate processing is the larger nonfit step. Exact fit runtimes are in each `fit_manifest.csv` (`elapsed_seconds`), and the preparation timing experiment is in `results/models/un_variants/timing/timing.csv`. Runtimes increase when many chains run concurrently.

New model fits use `code/11_model_variants.R`, not the archived replay command. Prepare inputs with `Rscript code/11_model_variants.R prepare`, then run `Rscript code/11_model_variants.R fit VARIANT 2 3000 12000 5 main` and `Rscript code/11_model_variants.R summarize VARIANT`. Every new fit writes to its own directory under `results/models/un_variants/`; completed fits and checkpoints are reused only when their keys match. The country-level level-change experiment first uses `Rscript code/11_model_variants.R simulate level_change_us_size`, then the same fit command with that case and an appropriate worker count. It contains multiple simulated arrays, each with two chains. These fits can take substantially longer than the summary commands.

`code/00_sampler.R` contains optional persistence-prior fields for new variants. With these fields unset, defaults reproduce the released chain features. `Rscript code/21_validate.R` checks the implementation, and `Rscript code/20_numerical_checks.R` independently recomputes reported summaries. The `recheck` mode of `code/10_models.R` also compares historical raw-source fingerprints. Historical receipts predate the optional fields and the numbered, reformatted scripts, so that metadata comparison fails against the current source tree. The old receipts are preserved; they are not rewritten to claim that current and historical source bytes match. Current numerical and build checks are recorded separately under `results/revision/`.

`code/03_prepare_imf_trade.py` documents the IMF source acquisitions and retained vintages; its header lists acquisition modes. Reproducing the observed trade comparisons uses the retained IMF responses through `code/03_economic.R`, without refreshing their vintage.

The manuscript sources are `paper/main.tex` and `paper/si.tex`. Working drafts and editing experiments have been removed. Numerical checks and the underlying analysis records remain in `results/`. The authors manually coded and checked the final request classifications against the official sources; reported classifications are unchanged. Earlier reading diagnostics are retained as historical records and are not reported as manual reliability statistics.

After the final build, run `python code/24_check_manuscript_files.py` to verify PDF and source hashes, references, the abstract and manuscript word limits, the supplement page target, and the current number bindings. It writes `results/revision/artifact_checks.json`.
